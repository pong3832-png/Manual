# 다른 컴퓨터에서 스케줄러 그대로 실행하기

이 문서는 `네이버 자동화 ing` 폴더 전체를 GitHub에 올려둔 상태에서, 다른 내 컴퓨터에 아무 폴더도 없다고 가정하고 스케줄러까지 다시 실행하는 방법을 정리한 것입니다.

전제:

```text
다른 컴퓨터에는 Python과 기본 모듈은 이미 있다.
작업 폴더는 비어 있다.
네이버 자동화 ing 폴더 전체는 GitHub에 올라가 있다.
Git을 사용해서 새 컴퓨터로 가져온다.
```

## 1. GitHub에서 전체 폴더 받기

다른 컴퓨터에서 작업할 위치로 이동합니다.

예시:

```powershell
cd C:\Users\내사용자명\Desktop
```

GitHub 저장소를 clone합니다.

```powershell
git clone https://github.com/pong3832-png/Naver_auto_program.git
```

clone이 끝나면 아래 폴더가 생깁니다.

```text
네이버 자동화 ing
```

이 폴더가 기존 컴퓨터의 `네이버 자동화 ing` 역할을 합니다.

작업 폴더로 이동합니다.

```powershell
cd "C:\Users\pong3\WORKING_HAPPY\네이버 자동화 ing"
```

블로그 글쓰기 폴더로 들어가려면:

```powershell
cd "네이버 블로그 글쓰기"
```

## 2. Git으로 받아지는 것

GitHub에서 clone하면 아래 파일과 폴더는 자동으로 받아집니다.

```text
네이버 블로그 글쓰기
네이버 이웃 추가
쿠팡 파트너스
cafe_news_자동실행_수강생공유용.py
.gitignore
```

`네이버 블로그 글쓰기` 안에서는 아래 파일들이 받아집니다.

```text
제미나이웹.py
스케줄러.py
skssj2627_db.csv
개발환경설정파일\requirements.txt
자동발행실행보조파일\gemini_web_runner.py
자동발행실행보조파일\scheduler_runner.py
자동발행실행보조파일\run_scheduled_post.ps1
자동발행실행보조파일\run_refresh_schedule.ps1
다른_컴퓨터에서_작업하기.md
```

## 3. Git으로 안 받아지는 것

아래 항목들은 보안이나 실행 기록 때문에 GitHub에 올리지 않습니다.

```text
네이버 아이디/비밀번호
텔레그램 봇 토큰
텔레그램 채팅 ID
Chrome 로그인 프로필
자동발행상태기록파일
Windows 작업 스케줄러 등록 정보
```

따라서 다른 컴퓨터에서는 이 항목들을 새로 설정해야 합니다.

## 4. Python 패키지 확인

Python과 기본 모듈이 이미 있다면 이 단계는 확인만 하면 됩니다.

블로그 글쓰기 폴더에서 실행합니다.

```powershell
cd "C:\Users\pong3\WORKING_HAPPY\네이버 자동화 ing\네이버 블로그 글쓰기"
```

필요 패키지가 이미 설치되어 있으면 넘어가도 됩니다.

확실히 맞추려면 아래 명령을 실행합니다.

```powershell
python -m pip install -r "개발환경설정파일\requirements.txt"
```

필요 패키지는 아래와 같습니다.

```text
selenium
Pillow
requests
pyperclip
schedule
```

## 5. Python 실행 경로 확인

다른 컴퓨터에서 Python 경로를 확인합니다.

```powershell
where python
```

예시 결과:

```text
C:\Users\내사용자명\AppData\Local\Programs\Python\Python313\python.exe
```

이 경로를 기억해둡니다.

## 6. 실행 보조 파일의 Python 경로 수정

이 단계가 중요합니다.

현재 실행 보조 파일 안에는 기존 컴퓨터의 Python 경로가 고정되어 있을 수 있습니다.

수정할 파일:

```text
네이버 블로그 글쓰기\자동발행실행보조파일\run_scheduled_post.ps1
네이버 블로그 글쓰기\자동발행실행보조파일\run_refresh_schedule.ps1
```

두 파일 안에서 아래 줄을 찾습니다.

```powershell
$pythonExe = "C:\Users\pong3\AppData\Local\Programs\Python\Python314\python.exe"
```

다른 컴퓨터에서 `where python`으로 확인한 경로로 바꿉니다.

예시:

```powershell
$pythonExe = "C:\Users\내사용자명\AppData\Local\Programs\Python\Python313\python.exe"
```

이걸 안 바꾸면 작업 스케줄러가 기존 컴퓨터의 Python 경로를 찾으려고 해서 실행에 실패합니다.

## 7. 네이버 계정 환경변수 설정

스케줄러로 자동 실행하려면 네이버 아이디와 비밀번호를 환경변수로 넣어야 합니다.

PowerShell에서 아래처럼 등록합니다.

```powershell
[Environment]::SetEnvironmentVariable("NAVER_ID", "네이버아이디", "User")
[Environment]::SetEnvironmentVariable("NAVER_PASSWORD", "네이버비밀번호", "User")
```

등록 후 PowerShell을 새로 열어야 반영됩니다.

확인:

```powershell
echo $env:NAVER_ID
```

비밀번호는 화면에 출력하지 않는 것이 좋습니다.

주의:

```text
네이버 아이디/비밀번호는 GitHub에 올리지 않습니다.
.env 파일에도 넣어서 GitHub에 올리면 안 됩니다.
```

## 8. 텔레그램 알림을 쓸 경우

텔레그램 알림을 쓰려면 아래 환경변수도 등록합니다.

```powershell
[Environment]::SetEnvironmentVariable("TELEGRAM_BOT_TOKEN", "봇토큰", "User")
[Environment]::SetEnvironmentVariable("TELEGRAM_CHAT_ID", "채팅ID", "User")
```

등록 후 PowerShell을 새로 엽니다.

텔레그램 알림을 쓰지 않으면 이 단계는 생략해도 됩니다.

## 9. Chrome과 로그인 프로필 준비

이 자동화는 Chrome을 사용합니다.

새 컴퓨터에 Chrome이 설치되어 있어야 합니다.

처음 실행하면 Gemini와 네이버 로그인 화면이 나올 수 있습니다. 새 컴퓨터에서는 보통 다시 로그인하는 것이 가장 안정적입니다.

기본적으로 사용되는 프로필 경로:

```text
C:\Users\내사용자명\ChromeGeminiBot
C:\Users\내사용자명\ChromeNaverBot_네이버아이디
```

처음 실행 후 Chrome이 열리면:

```text
Gemini 로그인
네이버 로그인
보안 확인 또는 캡차 확인
```

을 직접 처리합니다.

한 번 로그인되면 이후에는 같은 Chrome 프로필을 재사용합니다.

기존 컴퓨터의 로그인 상태를 그대로 옮기고 싶으면 아래 폴더를 직접 복사할 수도 있습니다.

```text
C:\Users\pong3\ChromeGeminiBot
C:\Users\pong3\ChromeNaverBot_네이버아이디
```

새 컴퓨터의 사용자 폴더에 같은 이름으로 붙여넣습니다.

하지만 Chrome 프로필 복사는 컴퓨터 환경 차이 때문에 오류가 날 수 있습니다. 권장 방식은 새 컴퓨터에서 직접 다시 로그인하는 것입니다.

## 10. skssj2627_db.csv 확인

## 11. 자동발행상태기록파일 처리

아래 폴더는 GitHub에 올리지 않습니다.

```text
네이버 블로그 글쓰기\자동발행상태기록파일
```

이 폴더에는 아래 같은 실행 기록이 들어갑니다.

```text
daily_schedule.json
coupang_used_products.json
coupang_selection_history.json
daily_category_rotation.json
coupang_angle_rotation.json
logs
```

다른 컴퓨터에 이 폴더가 없어도 스케줄러 실행 시 다시 만들어질 수 있습니다.

다만 기존 컴퓨터의 기록을 이어받고 싶으면 이 폴더는 직접 복사해야 합니다.

선택 기준:

```text
기존 사용 기록과 중복 방지 기록까지 이어받고 싶다
→ 자동발행상태기록파일 폴더를 직접 복사

새 컴퓨터에서 새 기록으로 시작해도 된다
→ 복사하지 않아도 됨
```

## 12. 수동 실행 테스트

작업 스케줄러에 등록하기 전에 먼저 수동 실행을 해봅니다.

블로그 글쓰기 폴더로 이동합니다.

```powershell
cd "C:\Users\pong3\WORKING_HAPPY\네이버 자동화 ing\네이버 블로그 글쓰기"
```

수동 실행:

```powershell
python "제미나이웹.py"
```

또는 실행 보조 파일로 테스트합니다.

```powershell
.\자동발행실행보조파일\run_scheduled_post.ps1 -PostType "일상"
```

쿠팡 글 테스트:

```powershell
.\자동발행실행보조파일\run_scheduled_post.ps1 -PostType "쿠팡"
```

처음 실행 때 확인할 것:

```text
Chrome이 정상 실행되는지
Gemini 로그인이 되어 있는지
네이버 로그인이 되어 있는지
skssj2627_db.csv를 찾는지
글쓰기 화면까지 접근되는지
```

수동 실행이 안 되면 스케줄러도 정상 실행되지 않습니다. 먼저 수동 실행부터 해결해야 합니다.

## 13. 스케줄러 등록

수동 실행이 정상이라면 작업 스케줄러를 등록합니다.

블로그 글쓰기 폴더에서 실행합니다.

```powershell
python "스케줄러.py"
```

이 명령은 아래 작업들을 Windows 작업 스케줄러에 등록합니다.

```text
NaverBlogAutoPost_01
NaverBlogAutoPost_02
NaverBlogAutoPost_03
NaverBlogAutoPost_04
NaverBlogAutoPost_05
NaverBlogAutoPost_06
NaverBlogAutoPost_07
NaverBlogAutoPost_08
NaverBlogAutoPost_09
NaverBlogAutoPost_10
NaverBlogAutoPost_RefreshDaily
```

`NaverBlogAutoPost_01`부터 `NaverBlogAutoPost_10`까지는 하루 글 발행 작업입니다.

`NaverBlogAutoPost_RefreshDaily`는 매일 새 스케줄을 다시 등록하는 작업입니다.

## 14. 스케줄러 등록 확인

작업 등록 확인:

```powershell
schtasks /Query /FO LIST /TN NaverBlogAutoPost_01
```

매일 새로고침 작업 확인:

```powershell
schtasks /Query /FO LIST /TN NaverBlogAutoPost_RefreshDaily
```

또는 Windows의 `작업 스케줄러` 앱에서 `NaverBlogAutoPost`로 시작하는 작업들이 있는지 확인합니다.

## 15. 스케줄러 실행 시 주의할 점

이 스케줄러는 Chrome을 띄워서 자동화합니다.

따라서 다른 컴퓨터에서도 아래 조건이 맞아야 합니다.

```text
컴퓨터가 켜져 있어야 함
Windows 사용자가 로그인되어 있어야 함
Chrome 실행이 막혀 있지 않아야 함
네이버/Gemini 로그인 세션이 살아 있어야 함
네이버 보안 확인이나 캡차가 뜨면 직접 처리해야 함
```

작업 스케줄러 등록 옵션에 `/IT`가 들어가므로, 사용자가 로그인된 상태에서 실행되는 방식입니다.

컴퓨터가 꺼져 있거나 로그아웃 상태이면 정상 실행되지 않을 수 있습니다.

## 16. 다른 컴퓨터에서 이후 업데이트 받기

기존 컴퓨터에서 코드를 수정하고 GitHub에 push했다면, 다른 컴퓨터에서는 아래 명령으로 최신 상태를 받습니다.

```powershell
cd "C:\Users\pong3\WORKING_HAPPY\네이버 자동화 ing"
git pull origin main
```

`skssj2627_db.csv`도 Git에 올라가 있으므로 수정 후 push하면 다른 컴퓨터에서 pull로 받을 수 있습니다.

## 17. 다른 컴퓨터에서 수정한 내용을 다시 GitHub에 올리기

다른 컴퓨터에서 파일을 수정했다면:

```powershell
git status
git add .
git commit -m "Update automation files"
git push origin main
```

단, 아래 항목은 GitHub에 올리면 안 됩니다.

```text
네이버 비밀번호
텔레그램 토큰
Chrome 프로필 폴더
자동발행상태기록파일

```

## 18. 전체 순서 요약

빈 컴퓨터에서 그대로 실행하려면 이 순서로 하면 됩니다.

```text
1. 원하는 위치에서 git clone
2. C:\Users\pong3\WORKING_HAPPY\네이버 자동화 ing\네이버 블로그 글쓰기 폴더로 이동
3. 필요하면 requirements.txt로 패키지 설치
4. where python으로 Python 경로 확인
5. run_scheduled_post.ps1, run_refresh_schedule.ps1의 $pythonExe 경로 수정
6. NAVER_ID, NAVER_PASSWORD 환경변수 등록
7. 텔레그램 알림을 쓰면 TELEGRAM_BOT_TOKEN, TELEGRAM_CHAT_ID 등록
8. python 제미나이웹.py 또는 run_scheduled_post.ps1로 수동 실행 테스트
9. Chrome에서 Gemini와 네이버 로그인 처리
10. 수동 실행이 정상인 것을 확인
11. python 스케줄러.py 실행
12. schtasks로 NaverBlogAutoPost 작업 등록 확인
```

## 19. 가장 많이 막히는 부분

다른 컴퓨터에서 가장 자주 막히는 부분은 아래입니다.

```text
run_scheduled_post.ps1 안의 Python 경로가 기존 컴퓨터 경로로 되어 있음
run_refresh_schedule.ps1 안의 Python 경로가 기존 컴퓨터 경로로 되어 있음
네이버 아이디/비밀번호 환경변수를 새 컴퓨터에 등록하지 않음
Gemini 또는 네이버 로그인이 새 컴퓨터에서 안 되어 있음
Chrome 보안 확인이나 캡차가 떠서 자동화가 멈춤
컴퓨터가 잠겨 있거나 로그아웃 상태라 작업 스케줄러가 Chrome을 못 띄움
```

문제가 생기면 먼저 아래 순서로 확인합니다.

```text
1. PowerShell에서 run_scheduled_post.ps1을 직접 실행해본다.
2. Python 경로가 맞는지 확인한다.
3. 네이버/Gemini 로그인이 되어 있는지 확인한다.
4. skssj2627_db.csv가 있는지 확인한다.
5. 그 다음 스케줄러.py를 다시 실행해 작업을 재등록한다.
```

## 20. 현재 폴더에서 GitHub에 올라가는 것과 안 올라가는 것

이 기준은 `네이버 자동화 ing` 저장소 안의 현재 `.gitignore` 설정과 실제 추적 상태를 기준으로 정리한 것입니다.

### GitHub에 올라가는 것

아래 항목들은 Git에서 추적하거나, 새로 수정하면 GitHub에 올리는 대상입니다.

| 항목 | 설명 |
| --- | --- |
| `네이버 블로그 글쓰기\.gitignore` | 블로그 글쓰기 폴더 안에서 제외할 파일 규칙 |
| `네이버 블로그 글쓰기\다른_컴퓨터에서_작업하기.md` | 다른 컴퓨터 작업/스케줄러 실행 안내 문서 |

### GitHub에 안 올라가는 것

아래 항목들은 GitHub에 올리지 않는 대상입니다.

| 항목 | 이유 |
| --- | --- |
| `네이버 블로그 글쓰기\__pycache__\` | Python 실행 캐시 |
| `네이버 블로그 글쓰기\자동발행실행보조파일\__pycache__\` | 보조 Python 파일 실행 캐시 |
| `네이버 블로그 글쓰기\자동발행상태기록파일\logs\` | 실행 로그 |
| `네이버 블로그 글쓰기\temp_blog_img_*.png` | 실행 중 만들어지는 임시 이미지 |
| `네이버 블로그 글쓰기\.env` | 계정 정보나 환경변수가 들어갈 수 있는 민감 파일 |
| `네이버 블로그 글쓰기\.env.*` | 환경변수/비밀값 파일 |
| `ChromeGeminiBot\`, `ChromeNaverBot\`, `ChromeNaverBot_*\` | Chrome 로그인 세션과 쿠키가 들어갈 수 있는 프로필 |
| `*.pyc`, `*.pyo`, `*.pyd` | Python 컴파일 결과물 |
| `.venv\`, `venv\` | 개인 컴퓨터별 Python 가상환경 |
| `logs\`, `*.log` | 실행 로그 |
| `node_modules\` | Node 패키지 폴더 |

### 다른 컴퓨터로 직접 옮겨야 할 수 있는 것

GitHub에는 올리지 않지만, 그대로 이어서 쓰고 싶으면 직접 복사할 수 있는 항목입니다.

| 항목 | 언제 복사하면 좋은가 |
| --- | --- |
| `ChromeGeminiBot` | Gemini 로그인 상태를 그대로 옮기고 싶을 때 |
| `ChromeNaverBot_네이버아이디` | 네이버 로그인 상태를 그대로 옮기고 싶을 때 |

`자동발행상태기록파일` 안의 JSON 파일은 이제 GitHub에 올라가도록 처리했으므로 직접 복사하지 않아도 됩니다. 다른 컴퓨터에서는 `git pull origin main`으로 중복 방지 기록을 받을 수 있습니다.

다만 Chrome 프로필은 컴퓨터 환경이나 Chrome 버전 차이 때문에 오류가 날 수 있습니다. 가능하면 다른 컴퓨터에서 직접 다시 로그인하는 쪽이 더 안정적입니다.

### 절대 GitHub에 올리면 안 되는 것

아래 값들은 파일에 적어서 GitHub에 올리지 않습니다.

```text
NAVER_ID
NAVER_PASSWORD
TELEGRAM_BOT_TOKEN
TELEGRAM_CHAT_ID
네이버 쿠키
Gemini/Google 로그인 쿠키
Chrome 프로필 폴더
.env 파일
secrets*.json 파일
토큰이 들어간 파일
```

이 값들은 다른 컴퓨터에서 Windows 환경변수로 다시 등록하는 방식이 안전합니다.
