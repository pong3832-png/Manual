# New Crawler Source Intake

새 체험단 사이트, 배송형, 기자단을 추가할 때 사용자가 Codex에게 보내면 좋은 자료 정리다. 아래 항목을 전부 한 번에 줄 필요는 없지만, 많이 줄수록 크롤러 구현과 QA가 빨라진다.

## 먼저 보내줄 것

새 사이트마다 아래 블록을 채워서 보낸다.

```text
사이트 이름:
사이트 메인 URL:
캠페인 목록 URL:
캠페인 상세 URL 샘플 3~5개:
원하는 수집 범위: 방문형 / 배송형 / 기자단 / 전체
로그인 필요 여부: 필요 / 불필요 / 모르겠음
검색 또는 카테고리 페이지 URL:
마감임박/최신순/인기순 같은 정렬 URL:
현재 사이트에서 중요해 보이는 필드:
특이사항:
```

## URL 샘플 기준

각 사이트마다 최소한 아래 URL을 보내면 좋다.

- 캠페인 목록 첫 페이지
- 캠페인 목록 2페이지 또는 더보기 후 URL
- 방문형 상세 페이지 2개
- 배송형 상세 페이지 2개
- 기자단 상세 페이지 2개
- 오늘마감 또는 모집종료 상세 페이지 1개
- 지역/카테고리/플랫폼 필터가 적용된 URL 1~2개

없는 유형은 `없음`이라고 적으면 된다.

## 화면 캡처가 필요한 경우

URL만으로 판단이 어려우면 캡처도 같이 보낸다.

- 목록 카드가 보이는 화면
- 상세 페이지 상단 정보 영역
- 제공내역/리워드가 보이는 영역
- 신청기간/발표일/체험기간이 보이는 영역
- 방문 주소 또는 배송 조건이 보이는 영역
- 기자단 원고료/작성 조건이 보이는 영역
- 로그인이 필요하다고 나오는 화면

## 방문형에서 특히 필요한 것

- 주소가 상세 페이지에 있는지
- 지도나 업체명만 있고 주소가 없는지
- 지역명이 제목에만 있는지
- 방문 가능 지역이 여러 개인지
- 체험 시간이 정해져 있는지
- 예약 필수/당일 방문/주차 같은 조건이 있는지

## 배송형에서 특히 필요한 것

- 상품 제공인지, 포인트/원고료인지
- 배송비 조건이 있는지
- 리뷰 채널이 블로그/인스타/쇼핑몰 리뷰 중 무엇인지
- 제품 카테고리가 무엇인지
- 실물 배송 없이 쿠폰/이용권 형태인지
- 주소 없이도 캠페인으로 노출해도 되는지

## 기자단에서 특히 필요한 것

- 원고료 또는 포인트가 표시되는지
- 작성 채널이 블로그/카페/인스타/기타 중 무엇인지
- 가이드 원고 제공 여부
- 사진 제공 여부
- 직접 체험이 필요한지, 원고 작성만 하면 되는지
- 키워드/링크 삽입 조건이 강한지

## 로그인이나 쿠키가 필요한 경우

비밀번호, 계정, 쿠키 값을 채팅에 직접 붙여넣지 않는다.

대신 아래처럼 알려준다.

```text
로그인 필요: 예
로그인해야 보이는 정보: 상세 주소 / 신청 조건 / 제공내역 / 원고료
내가 브라우저에서 로그인 가능: 예
쿠키 또는 토큰을 .env에 넣어도 됨: 사용자 승인 후
```

실제 쿠키/토큰이 필요하면 `.env` 변수명만 정하고, 값은 로컬 파일에 넣는다. 예: `NEW_PLATFORM_COOKIE`.

## 네트워크 자료가 있으면 좋은 경우

사이트가 HTML에 데이터를 바로 보여주지 않고 API로 가져오면 아래 자료가 있으면 좋다.

- Chrome 개발자도구 `Network` 탭에서 캠페인 목록 API URL
- 상세 페이지 API URL
- API 응답 샘플 일부
- 페이지네이션 파라미터 이름
- 카테고리/지역 필터 파라미터 이름

잘 모르겠으면 URL과 캡처만 보내도 된다. API는 Codex가 확인한다.

## 우선순위 판단 기준

먼저 추가하기 좋은 사이트는 아래 조건을 만족한다.

- 로그인 없이 목록과 상세를 볼 수 있다.
- 캠페인 수가 많다.
- 마감일과 상태가 명확하다.
- 방문형/배송형/기자단 타입이 구분된다.
- 상세 URL이 안정적이다.
- 주소, 제공내역, 원고료 같은 핵심 필드가 텍스트로 표시된다.

나중에 하는 것이 좋은 사이트는 아래에 해당한다.

- 로그인 없이는 거의 안 보인다.
- 무한 스크롤만 있고 URL/page 파라미터가 없다.
- 이미지 안에만 핵심 정보가 있다.
- 매 요청마다 차단/캡차가 뜬다.
- 캠페인 수가 적거나 중복이 많다.

## 사용자에게 받을 최종 요청 예시

```text
새 사이트 추가 요청

사이트 이름: 예시체험단
메인 URL: https://example.com
목록 URL: https://example.com/campaigns
상세 URL 샘플:
- https://example.com/campaigns/1001
- https://example.com/campaigns/1002
- https://example.com/campaigns/1003

수집 범위: 배송형 먼저, 이후 방문형
로그인 필요: 목록은 불필요, 신청 조건은 필요
중요 필드: 마감일, 제공내역, 리뷰 채널, 배송 조건, 카테고리
특이사항: 무한 스크롤이고 더보기 버튼이 있음
```

## Codex 작업 시작 전 확인 순서

1. 이 문서의 사용자 입력 블록을 확인한다.
2. 기존 `scripts/crawler/crawl.cjs`의 플랫폼별 수집 패턴을 재사용할 수 있는지 본다.
3. 새 플랫폼이 `visit`, `delivery`, `reporter` 중 어디에 들어갈지 먼저 정한다.
4. 샘플 URL 3~5개로 필드 추출 가능성을 확인한다.
5. 대량 크롤, 로그인, 외부 API 호출, Supabase 쓰기는 사용자 승인 전 실행하지 않는다.
6. 구현 후 최소 검증은 제한 크롤, `npm run crawl:check`, 관련 QA fixture 순서로 진행한다.
