# Launch Priorities

마지막 갱신: 2026-05-07 KST

이 문서는 `camp-platform` 출시 전 해야 할 일을 우선순위로 관리하기 위한 체크리스트다. 목표는 "여러 체험단 사이트를 한 번에 모아, 사용자가 신청할 캠페인을 가장 빨리 찾게 하는 서비스"로 출시하는 것이다.

## Product Direction

- 포지션: 체험단 사이트가 아니라 체험단 검색 엔진.
- MVP 범위: 방문형 체험단 중심.
- 핵심 강점: 여러 플랫폼 통합, 카테고리 전체보기, 지역/지도 탐색, 빠른 신청.
- 출시 기준: 데이터 수집 성공 플랫폼 비율 70% 이상일 때만 발행.

## P0 - Launch Blockers

- [ ] 순차 데이터 수집 흐름 검증
  - 사용자가 `powershell -NoProfile -ExecutionPolicy Bypass -File "C:\Users\itwill\자동화 공부\camp-platform\scripts\ops\run-crawl.ps1"`을 직접 실행.
  - `public/crawl-status.json`, `public/data-quality.json`, `.cache/crawl-artifacts/quality-gate.json`을 확인.
  - quality gate 통과 시에만 `public/campaigns.json`/Supabase 반영되는지 확인.
  - 실패 시 실패 플랫폼 로그와 quality gate 결과부터 확인.

- [ ] 데이터 품질 기준 확인
  - 성공 플랫폼 비율 70% 이상.
  - 좌표 70% 미만이면 지도 품질 경고로 보고, 홈/탐색에서는 좌표 없는 캠페인도 목록에서 확인 가능해야 한다.
  - 특정 플랫폼의 open 캠페인 수가 이전 대비 80% 이상 급락하면 이번 결과를 격리하고 이전 공개 데이터를 보존한다.
  - `기타` 카테고리 비중이 출시 화면에서 과도하지 않은지 확인.
  - 마감 지난 캠페인이 open 목록에 남지 않는지 확인.

- [ ] 홈 UX를 탐색 시작점으로 개편
  - Top5 나열보다 `전체보기` CTA를 중심에 둔다.
  - 맛집, 카페, 뷰티, 숙박, 체험, 지역별 전체보기로 이어지게 한다.
  - "12개 플랫폼 통합", "최근 업데이트", "전체 캠페인 수"를 작게 노출한다.

- [ ] 캠페인 카드 신청 판단 정보 강화
  - 제목, 지역, 카테고리, 혜택, D-day, 플랫폼, 신청 버튼을 한눈에 보이게 한다.
  - 상세 모달 없이도 신청할지 판단 가능해야 한다.

- [ ] 출시 전 QA 체크리스트 통과
  - `docs/release-checklist.md`의 Launch Decision Gate를 기준으로 공개 가능 여부를 판단한다.
  - 데이터 QA, 홈/탐색/지도/카드/모바일 QA를 확인한다.
  - P0 보류 조건이 하나라도 있으면 공개 전에 수정한다.

## P1 - Strong Differentiators

- [ ] 지도 화면을 핵심 탐색 기능으로 강화
  - 지도 표시 가능 캠페인 수와 전체 캠페인 수를 함께 보여준다.
  - 좌표 없는 캠페인은 목록에서 확인 가능하다는 신뢰 문구를 둔다.
  - 지역/카테고리 필터와 지도 결과가 자연스럽게 연결되게 한다.

- [ ] 탐색 페이지 전체보기 흐름 정리
  - 홈에서 카테고리 클릭 시 해당 카테고리 전체 목록으로 이동.
  - 지역 클릭 시 해당 지역 전체 목록으로 이동.
  - 정렬은 마감임박, 신규, 가까운 순 중심으로 둔다.

- [ ] 최근 업데이트 신뢰 지표 추가
  - 최근 업데이트 시각.
  - 통합 플랫폼 수.
  - 확인된 캠페인 수.
  - 마감 캠페인 자동 제외 메시지.

- [ ] 시각 요소 보강
  - 원본 체험단 사이트의 캠페인 이미지를 무단 복사/저장해서 쓰지 않는다.
  - 외부 이미지 URL을 그대로 노출하는 방식도 사이트 약관, 저작권, 장애 대응 리스크가 있으므로 출시 MVP에서는 기본값으로 쓰지 않는다.
  - 카테고리별 자체 제작 이미지, 라이선스 확인된 stock 이미지, generated image, 아이콘/컬러 패턴을 우선 사용한다.
  - 플랫폼 로고는 사용 허락 또는 브랜드 가이드 확인 전까지 텍스트 배지로 대체한다.
  - 캠페인 카드에는 이미지가 없어도 덜 밋밋하게 보이도록 카테고리 색상, 지역 배지, D-day 강조, 혜택 텍스트를 강화한다.

## P2 - After Launch

- [ ] 배송형/기자단/구매형을 별도 타입으로 복원할지 결정.
- [ ] VPS 또는 클라우드 서버에서 자동 실행하도록 이전.
- [ ] 플랫폼별 수집 코드를 파일 단위로 분리.
- [ ] 실패 플랫폼만 재실행하는 운영 명령 추가.
- [ ] 즐겨찾기/신청 현황 기반 개인화 추천 강화.
- [ ] 광고/수익화 지면을 사용자 탐색 흐름을 해치지 않는 위치에 배치.
- [ ] 원본 플랫폼과 이미지/데이터 제휴 또는 이용 허락을 받을 수 있는지 검토.

## Operating Rules

- 수집 실행은 사용자가 직접 실행한다.
- 코드 보완자는 실제 수집/발행/배포/스케줄러 등록을 실행하지 않고 명령과 코드를 제공한다.
- `public/*.json`, `.cache`, `logs`는 실행 산출물이므로 임의 수정하지 않는다.
- 작업 후에는 가장 작은 검증 명령을 먼저 실행한다.

## Next Recommended Step

1. 현재 실행 중인 순차 크롤이 끝날 때까지 기다린다.
2. 완료 후 `public/crawl-status.json`, `public/data-quality.json`, `.cache/crawl-artifacts/quality-gate.json`을 확인한다.
3. blocked면 `gangnam`, `reviewplace`, 포포몬 D-day, 좌표 warning부터 본다.
4. passed 또는 passed_with_warnings면 홈/탐색/지도/모바일 QA로 넘어간다.
