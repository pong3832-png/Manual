# Frontend Guide

## Purpose

이 문서는 `camp-platform` 프론트엔드 작업 규칙을 정의합니다.
`AGENTS.md`가 상위 운영 규칙이라면, 이 문서는 반응형 웹 구현과 파일 책임 분리에 집중합니다.

## Product Shape

- 모바일 우선 반응형 웹으로 설계한다.
- 핵심 사용 맥락은 빠른 탐색, 지역 확인, 상태 추적이다.
- 지도, 리스트, 필터, 카드, 모달이 동시에 존재할 수 있으므로 정보 계층이 중요하다.

## Breakpoint Mindset

- 모바일 기준 폭: `360px` ~ `430px`
- 태블릿 기준: `768px` 전후
- 데스크톱 기준: `1024px` 이상

브레이크포인트 수를 늘리기보다, 레이아웃 전환 지점을 명확하게 유지한다.

## File Responsibility

- `src/app/App.jsx`: 탭 셸, 전역 필터, URL 상태 동기화, 페이지 조립
- `src/pages/`: 페이지 단위 UI와 상위 상호작용
- `src/features/*`: 기능별 컴포넌트, 훅, 도메인 로직
- `src/shared/api/`: Supabase 같은 공통 API 진입점
- `src/shared/config/`: 플랫폼/카테고리/표시 상수
- `src/shared/assets/`: 공용 정적 자산

## Layout Rules

- 하단 탭이 있을 때 본문 하단 여백을 충분히 확보한다.
- 카드 그리드는 폭이 부족하면 열 수를 줄이고, 텍스트 가독성을 유지한다.
- 필터 영역은 접기보다 우선순위가 높은 필터만 상단에 남긴다.
- 지도와 리스트가 함께 있을 때 모바일에서는 스캔 가능한 순서를 우선한다.
- 모달은 작은 화면에서 상단과 하단이 잘리지 않게 최대 높이와 내부 스크롤을 분리한다.

## State Rules

- URL로 표현 가능한 필터 상태는 가능한 한 URL과 동기화한다.
- 데이터 shaping은 페이지 안에서 반복하지 말고 `lib` 또는 `hooks`로 올린다.
- 인증 상태, 즐겨찾기, 지원 상태처럼 사용자 종속 데이터는 데이터 fetching과 UI 표시 책임을 분리한다.

## CSS Rules

- 전역 스타일은 정말 전역인 경우에만 `src/index.css`, `src/app/App.css`에 둔다.
- 특정 컴포넌트 표현 규칙은 해당 컴포넌트 가까이에 유지하는 방향을 우선한다.
- spacing, radius, color, surface 패턴은 반복되면 토큰화 후보로 본다.
- 화면이 좁아졌을 때 글자 크기를 무리하게 줄이지 말고 레이아웃을 바꾼다.

## UX Rules

- 사용자는 빠르게 “어디인지”, “무슨 체험단인지”, “마감이 얼마나 남았는지”를 알아야 한다.
- D-day, 카테고리, 플랫폼, 위치는 카드에서 우선순위가 높은 정보다.
- 지도 화면에서는 좌표 정확도보다 먼저 사용자가 지역 흐름을 이해할 수 있어야 한다.
- 상태 화면에서는 사용자가 지금 무엇을 해야 하는지 다음 행동이 보여야 한다.

## Definition Of Done

프론트 변경은 아래를 충족해야 한다.

1. 모바일에서 주요 흐름이 가로 스크롤 없이 동작한다.
2. 하단 탭, 모달, sticky UI가 본문을 가리지 않는다.
3. 데이터 fallback과 빈 상태가 깨지지 않는다.
4. `npm run build`와 `npm run lint`를 통과한다.
